LLM Provider & Model Analysis

Free and paid API tiers — availability, economics, and a 1–2 year outlook

Prepared for the Noviq API Integration tab · Data current as of July 2026 · Internal engineering & product reference

How to read this document — and its one hard limitation.

  • Sections 1–4 are observed fact, drawn from provider documentation and pricing trackers cited in Section 9. These are verifiable today.
  • Section 6 (the 1–2 year outlook) is a projection, not a fact. No provider publishes a guarantee that a free tier will still exist in 2028. What providers do publish is a model deprecation floor ("this model will not retire sooner than X"), and that is a different promise: it covers a specific model ID, not the commercial tier it sits in. Section 6 therefore separates EVIDENCE (published dates and policies) from JUDGEMENT (our inference). Do not present the judgement column to a customer as a commitment.
  • Free-tier numbers decay fastest of anything here. Rate limits changed materially at least three times across the industry in the last twelve months (Section 5). Section 8 specifies how the app should handle this: the limits belong in a refreshable config, never in compiled constants.

1. Executive summary

  1. Free inference is real, permanent, and commercially usable — but only at prototype scale. Six providers (Google AI Studio, Groq, Cerebras, Mistral, OpenRouter, GitHub Models) run rate-limited free tiers with no expiry date, not time-boxed trials. None is viable as a production backend for a multi-user deployment; ceilings land between 50 and ~14,400 requests/day.
  2. The cheapest capable paid model now costs about 1/200th of the most expensive. DeepSeek V4-Flash is $0.14/$0.28 per million tokens; GPT-5.4 Pro is $30/$180. For Noviq's workload — retrieval-grounded answering over a fixed corpus — the mid-tier band ($0.10–$3.00 input) is where the decision actually lives.
  3. Price per unit of capability is still falling, but the rate is decelerating. The 10× per-year collapse of 2021–2025 is not expected to hold; 3–5× annually through 2027 then tapering to 1.5–2× is the mainstream projection. Budget accordingly: do not model 2028 costs on a 10× extrapolation.
  4. The largest integration risk is not price, it is model churn. Fourteen widely-used model IDs have publicly scheduled shutdown dates between July and December 2026 alone, including GPT-4o, GPT-4 Turbo, o1, Gemini 2.5 Pro and Gemini 2.5 Flash. Any provider list we hardcode will be partially dead within nine months.
  5. Design consequence for the integration tab: treat the provider/model catalogue as remote, versioned data with a live capability probe, not as a static dropdown. Section 8 specifies this.

3. Free-tier detail — ranked for our use case

Ranking criterion is Noviq-specific: retrieval-grounded legal answering, which means a large prompt (~8K tokens of retrieved passages) and a modest completion. This inverts the usual ranking — token-volume tiers matter less than context ceiling, and a tier with a hard 8K context is unusable no matter how many tokens/day it grants.

#ProviderVerdict for RAGReasoning
1GroqSTRONG128K context, 14,400 RPD, sub-second latency. The only free tier that could plausibly carry a single-user demo of Noviq end to end. Token-per-minute cap (6,000 TPM) is the real constraint: an 8K-token RAG prompt means roughly one query per 80 seconds sustained.
2Google AI StudioSTRONGUp to 1M context free — by far the most headroom for large retrieved context. 250–1,000 RPD is adequate for demos. Main caveat is the data-usage term outside EU/UK/EEA.
3OpenRouterGOOD1,000 RPD after a one-time $10 unlock, one key across ~30 models, and no training-on-data clause. Best choice for letting a user try several models, which is precisely what the integration tab is for.
4MistralCONDITIONAL~1B tokens/month is enormous and 256K context is ample — but the free tier is contingent on allowing training on submitted data. For a legal corpus that is a policy decision, not an engineering one.
5GitHub ModelsLIMITEDFine for CI smoke tests of the integration path. Context down to 8K on some models and low RPM rule it out for user-facing work.
6CerebrasUNSUITABLE1M tokens/day is the headline, but the 8,192-token free context cap is below our typical prompt size. It would truncate retrieved passages — the exact failure mode that produces ungrounded answers. Excellent for short-prompt/high-volume work; wrong for ours.
7Cloudflare Workers AIUNSUITABLE2K–8K context. Same disqualification as Cerebras, with a smaller allowance.
8CohereBLOCKEDTechnically a good fit (128K, citation-native), but the free key is non-commercial only. Cannot ship it to a paying institution.

The tokens-per-minute trap. Free tiers advertise requests/day, which flatters them. RAG traffic is token-heavy per request, so the binding constraint is almost always TPM, not RPD. Groq's 14,400 RPD looks like 10 requests/minute of headroom, but at 6,000 TPM and an 8K-token prompt the true sustained rate is closer to 0.75 requests/minute. The integration tab should show users the effective rate at our average prompt size, not the provider's headline number — otherwise every free-tier user will hit 429s they were told wouldn't happen.

Two discounts that change the arithmetic more than model choice does.

  • Prompt caching — up to 90% off cached input (OpenAI and Anthropic; DeepSeek prices cache hits at $0.07 vs $0.27). Noviq's system prompt plus grounding instructions are identical on every single query. That prefix is pure cached input. This is the single highest-leverage cost optimisation available to us and it requires no model change.
  • Batch processing — 50% off, applicable to anything not user-interactive: summary generation, re-indexing passes, evaluation runs.
  • Stacked, these bring effective cost to roughly 25% of list price. A $3.00/M model run well is cheaper than a $1.00/M model run naively.

5. Current state — what has actually changed recently

This section exists because it is the empirical basis for Section 6. Every item is an observed change, not a prediction.

  • Late 2025 — Google cut Gemini free-tier rate limits by 50–80%. The largest single free-tier reduction observed. Free access survived; its generosity did not.
  • May 2026 — Google removed Gemini Pro from the free tier entirely. Free now covers Flash and Flash-Lite only. Pattern: the frontier model leaves the free tier while the cheap model stays.
  • 31 May 2026 — Cerebras cut its free model catalogue from roughly a dozen models to two (gpt-oss-120b and GLM-4.7), and capped free context at 8,192 tokens.
  • Ongoing — OpenRouter's free ceiling is now credit-gated: 50 RPD below $10 lifetime spend, 1,000 RPD above it. Free access converted into a customer-acquisition funnel rather than withdrawn.
  • Ongoing — xAI's $150–175/month free credit programme has changed terms repeatedly and is contingent on data sharing.
  • Stable — Groq has maintained a no-credit-card, no-token-charge developer tier across the whole period, gated only by rate limits. It is the most stable free tier we can identify by track record.

The pattern across all six observations. Free tiers are not being withdrawn — they are being repriced downward in capability. Providers keep the zero-dollar entry point because it is their acquisition channel, but they steadily remove from it: first the frontier models, then the context window, then the model breadth. This matters for the projection in Section 6 far more than any single announcement, and it points to a specific conclusion: plan for free tiers to persist but degrade, rather than for them to disappear.

7. Non-price selection criteria

Price is the easiest axis to compare and rarely the one that decides. For a legal-corpus product these matter more:

  • Training on submitted data. Mistral's free tier requires opt-in to training. Google uses free-tier prompts to improve models outside EU/UK/EEA. xAI's free credits are explicitly a data-sharing exchange. OpenRouter and Cohere state no-training terms. For any deployment handling non-public documents this is a gating criterion, not a preference — and it should be surfaced as a visible tag in the integration UI, not buried in documentation.
  • Licence restrictions. Cohere's free key is non-commercial. A free tier that cannot legally be used in a customer deployment has zero value to us regardless of its limits.
  • No SLA on free tiers. Universal. Free tiers carry no availability guarantee of any kind.
  • Silent quality reduction. Free endpoints may serve lower-quantisation weights or reduced context than the paid endpoint for the same nominal model. Identical model ID does not imply identical output quality across tiers.
  • Data residency. Mistral offers EU residency; most others do not offer regional guarantees on free tiers.

8. Implications for the API Integration tab

These follow directly from the findings above and are the actionable output of this analysis.

8.1 The catalogue must be data, not code

  • Given a ~12-month model-ID half-life (§6.3), a compiled-in provider/model list guarantees a broken dropdown within a year. Store the catalogue as a versioned, refreshable config document — shipped with a bundled default so the app works offline, updated out-of-band without a release.
  • Each model entry should carry at minimum: provider, model_id, tier (free / trial / paid), context_window, input_price, output_price, rpm, tpm, rpd, trains_on_data, commercial_use_allowed, known_shutdown_date.
  • known_shutdown_date drives a visible deprecation warning in the UI. A user selecting GPT-4o today should be told it stops working on 23 October 2026 — before they build on it.

8.2 Tags the user actually needs

The request specified free/paid tags. Findings suggest these are necessary but insufficient — three of them encode disqualifying conditions that a free/paid split hides:

  • FREE permanent, rate-limited, no expiry
  • TRIAL one-off credits that will run out — must be visually distinct from FREE, or users will build on a tier that vanishes
  • PAID metered from the first token
  • TRAINS ON YOUR DATA Mistral free, Google free outside EU/UK/EEA, xAI credits
  • NON-COMMERCIAL Cohere free
  • CONTEXT-LIMITED below our RAG prompt size — Cerebras free (8K), Cloudflare (2K–8K)
  • RETIRING < 90 DAYS derived automatically from known_shutdown_date

8.3 Validate the key against the model, not just the provider

  • On key entry, issue a minimal probe call to the selected model and report the concrete result. A key valid for a provider is routinely not entitled to a given model — the Gemini free tier is the live example: a valid key returns 404/403 on Pro but 200 on Flash.
  • Probe and record the actual context ceiling where cheaply possible, rather than trusting the catalogue. Section 5 shows published free-tier context changing without notice.

8.4 Surface the effective rate, not the headline

  • Per §3, compute expected sustainable throughput from TPM ÷ our measured average prompt size and display that. Showing Groq's "14,400 requests/day" when the true sustained ceiling is under one request per minute would be the most likely source of user-reported "it's broken" tickets.
  • This is a specific instance of a failure pattern already recorded for this project: a number shown to a user must be derived from the thing itself, never re-estimated from a headline figure.

8.5 Prefer aggregators for breadth, direct keys for production

  • OpenRouter first. One integration yields ~30 free models plus most paid ones, and absorbs upstream model churn on our behalf — directly mitigating the §6.3 half-life risk.
  • Direct provider keys second, for customers who need a contractual relationship, data-residency guarantees, or a zero-retention DPA. An aggregator adds a party to the data path, which matters for the data-boundary question.

8.6 Enable prompt caching wherever the provider supports it

  • Per §4, this is up to 90% off input and our prompt prefix is constant across every query. It should be a default-on behaviour in the provider adapter, not a user-facing toggle.
