# Phase 1 Data Model — Notice Assist

## Persistence

### Table `notice_assist_session` (additive Postgres migration)

| Column | Type | Notes |
|---|---|---|
| `conversation_id` | text PRIMARY KEY | one assist session per conversation |
| `state_json` | text (JSON) | serialized `NoticeAssistState` (see below) |
| `updated_at` | timestamptz / bigint | last write |

Repository seam: `services/assistant/capabilities/notice_assist/session.rs` —
`save/load/delete(pool, conversation_id, …)`. Mirrors `one_ask_session` (F010). Additive only
(Constitution Development Constraints).

## Aggregate: `NoticeAssistState` (`state_json`)

```
NoticeAssistState {
  phase: Phase,                 // Analyze | Gather | Ground | Draft | Done
  frame: Frame,
  drafted_reply: Option<String> // cached final reply (for resume/export)
}
```

`#[serde(default)]` on every field; tolerate unknown keys (forward-compat, matches one-ask).

### `Frame` (the universal argument frame — the ONLY predefined structure)

```
Frame {
  document_kind: DocKind,          // ShowCause | Warning | ExplanationCall | AuditPara | Other
  kind_confidence: f32,            // 0.0–1.0 (model self-report; template selection only)
  allegations: Vec<Allegation>,    // 1..N; empty ⇒ fallback (R4)
  relief_or_explanation_sought: Option<String>,
  forum: Option<String>,           // issuing / deciding authority
  deadline: Option<String>,        // date | "within N days" | None
  cited_rule_text: Vec<CitedRule>, // filled in Ground phase from the corpus
}
```

### `Allegation`

```
Allegation {
  id: u32,                         // stable slot key
  text: String,                    // what is alleged/objected (from the document)
  invoked_rule: Option<String>,    // rule/section named against the officer (as written)
  invoked_authority: Option<String>,
  questions: Vec<SlotQuestion>,    // model-DERIVED questions to rebut THIS allegation
}
```

### `SlotQuestion` (dynamic slot — not predefined)

```
SlotQuestion {
  id: u32,
  question: String,                // generated by the model from the document
  answer: Option<String>,          // officer's answer (verbatim, masked upstream)
  status: SlotStatus,              // Open | Filled | Gap
}
```

### `CitedRule` (grounding output)

```
CitedRule {
  invoked_ref: String,             // the rule as named in the notice
  found: bool,                     // located in the corpus?
  verbatim: Option<String>,        // exact provision text (citation gate)
  citation: Option<Citation>,      // canonical hierarchical citation (Principle XI)
}
```

## State transitions (phase machine)

```
Analyze ──(extraction ok, allegations≥1)──▶ Gather
Analyze ──(parse fail | empty | model down)──▶ Gather   (with 1 fallback question, R4)
Gather  ──(all questions Filled|Gap  OR  officer says "draft")──▶ Ground
Ground  ──(retrieve cited rules; flag misses)──▶ Draft
Draft   ──(compose reply, cache)──▶ Done
Done    ──(officer edits a fact / "revise")──▶ Gather   (re-open the affected slot)
```

Idempotency: re-entering `Gather` never re-asks a `Filled`/`Gap` slot (US3 AS-1/AS-2). Analyze
runs once per document and is cached in `frame` (re-run only on a new attachment).

## Validation rules

- `allegations` non-empty after Analyze OR the fallback question is present (never both empty).
- A `SlotQuestion.status = Filled` requires non-empty `answer`.
- Transition to `Draft` requires `cited_rule_text` populated (each invoked rule → found or
  explicitly `found=false`).
- Legal text in the reply MUST come from `CitedRule.verbatim` (corpus), never the model's memory
  (FR-008, Principle XI). A `found=false` rule renders an ⚠ "text not located — supply it" line.

## Relationships / reuse

- `conversation_id` ↔ existing `chat_message` / conversation memory (F015); attachment source ids
  via F021 `sources.conversation_id`.
- `Citation` = the existing assistant citation type (rendered by the current citation gate).
- Draft assembly reuses `services/drafting` compose/export; export via `export_draft`.
